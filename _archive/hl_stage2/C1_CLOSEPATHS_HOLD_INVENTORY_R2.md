## Surfaces and join keys

- `send_attempts.csv`: append-only `attempt_id` and its revisions; latest row **by exact attempt_id** is current status, earlier `pending_send` is immutable historical evidence, **not** a second unresolved current send. Fields: `leader_fill_id,intent_id,cloid,status,terminal_state,operator_action,copy_size,reduce_only_sent,exchange_order_id,notes`. A *second* physical GTC may receive TWO independent attempt rows, one prewire `pending_send` (without OID) and another `ORDER_RESTING` with OID; the OID-based sweep cannot retire the unindexed pending row: **REV2 OBSERVED RED**, requires separate cloid/attempt correlation. Never report zero outstanding just because one OID row filled.
- `reconciliation.csv`: `event,status,action,reject_category,terminal_state,engine_can_send,manual_net,exchange_net,leader_fill_id,intent_id,coin,exchange_order_id,notes`. A source may emit multiple supplemental rows with distinct `status`; generic `AUTHORISED_CLOSE_REFUSAL` is **not itself** root cause. Some statuses leave `terminal_state,manual_net,exchange_net` empty. Separate joins via intent/fill ID are required.
- `close_escalations.json`: keyed by wallet::coin; `state=OPEN,leader_fill_id,intent_id,reason,terminal_rule=ENGINE_SLEEVE_AND_FRESH_EXCHANGE_NET_BOTH_FLAT`. Later outer `_finish` can overwrite specific reason with generic status. This is **OBSERVED RED**: `CLOSE_PROOF_HOLD_UNREADABLE_NET` in recon vs `SEND_NOT_ATTEMPTED_CLOSE_PROOF_HOLD` in RED JSON.
- `standing_closes.json`: recovery OID, size, side, intent ID, sleeve; an outstanding resting order is **not a terminal close fill**. Only actual `live_fills.csv` OID-matched fill and verified same-account net+owned sleeve may clear RED.
- `errors.csv`: exception/failure diagnostics; not a substitute for an actionable close RED/reconciliation. Audit write failures need explicit investigation.

### General on-disk rules

**Authorised EXIT/REDUCE**, `send_if_allowed` failed via `_finish(False,status)`: invokes `_journal_authorised_close_refusal(intent,status)`, opens RED and appends `CLOSE_ESCALATION / AUTHORISED_CLOSE_REFUSAL` action `RECONCILE_OWED_CLOSE_BEFORE_RETRY`, `engine_can_send=False`, `reject_category=status`, unless earlier terminal fill is already recorded. Thus any branch below that says **RED+REFUSAL** has that root-specific (or outer generic) row. **No physical order** for a pre-send gate rejection. Exceptions inside send may re-journal a `SEND_EXCEPTION_<class>` reason and re-raise; verify `errors.csv`. If `intent.send_allowed=False`, this is **not authorised** and does not necessarily produce the close RED; inspect original `order_intents.csv` / dispatcher terminal instead.
