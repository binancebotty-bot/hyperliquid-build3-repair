## The arming change that drives most of this board

`ConfigManager.master_real_orders_enabled` is `self.send_mode != "OFF"`
(`HL_Live_Copy_Service_Core.py:4069-4071`); `send_mode` comes from `_send_mode_of`
(`:4005-4022`), which honours `global_controls.send_mode` first and otherwise reads legacy
`auto_send_enabled`. `SenderGateway._master_gate_reason` (`:5650-5665`) is consulted **inside**
`_place_order` (`:5711-5715`) and returns `MASTER_REAL_ORDERS_OFF` before any exchange call when the
mode is OFF.

Every fixture that writes `"auto_send_enabled": False` and then calls `_send_real` directly now gets
`ORDER_REJECTED`, zero fake-exchange calls and no audit rows — the gate refusing, not the behaviour
under test. Flipping that one literal to `True` in a scratch copy turns most of this board green, so
those failures are counted as harness, not engine.

## WORST FIRST — the five most dangerous real defects

Ranked by what a user would actually suffer. Only the top entry is on this board's files; the other four
are the assertions I confirmed are **not** false and that no other row on this board covers.

1. **Send-time wallet-mode read fails OPEN** — `HL_Live_Copy_Service_Core.py:8084-8086`. A wallet config that cannot be parsed at the final gate returns "no block", so an order the operator's config may have forbidden goes to the exchange. Exposure is worst on **closes**: the user switches a wallet to OFF or CLO to stop traffic and a config read error silently re-arms it. This is the only real defect found in the 17 files.
2. **Shipped by design, worth stating: standing-close recovery orders are NOT reduce-only** (`:7230-7248`, Boss ruling 12 Oct). `test_core_engine_gaps.py` O2 and `test_core_run4_fixes.py` R1 were written against the older rule. The guard is `guard_standing_closes()` plus sizing from a fresh net read — if either of those degrades, a close limit can flip a position. Not a defect today; the tests no longer pin it.
3. **`UNOWNED_INVENTORY` fires before the exposure caps** (`:5373-5379`). With sending armed, any coin whose exchange net the engine cannot read blocks entries regardless of cap configuration — correct for safety, but it means a follower-exposure outage silently stops all entries while the screen reports a cap reason. `test_core_network_and_global_controls.py` G0/G2 encode the pre-ENG-016 expectation.
4. **Unknown intent at the physical call is a hard refusal** (`:5656-5662`, `MISSING_INTENT_CONTEXT`). Three test files call `_place_order` with no intent and are refused. In production this is the right default, but it means any future call site that forgets to pass `intent=` fails silently as a "gate refusal" rather than a code error — the 66 ALERT lines in the slot-pacing log are what an operator would see.
5. **The UI no longer writes account history or the P&L graph** (`:2601-2605`, early `return`). The engine owns `exchange_account_history.json` now. Anything still reading the UI's expectation — including `test_screen_run4.py`'s history and graph rows — is asserting a dead path; if the engine stops appending, the screen shows a frozen graph with no error.
